QuickPlotNode — 产品与合规模块说明
===================================

1. 一句话定位
----------------
QuickPlotNode 不是“画图节点”，而是“让异常一眼可见的审计证据可视化节点”。其目的是帮助审计人员在最短时间内判断哪些现象值得继续查证，提供可追溯的可视化证据，而非结论或解释。

2. 在审计流程中的合理位置
--------------------------
QuickPlotNode 一般位于：

ExcelLoader → ColumnMapper → NullValueCleaner → (CommonMetrics / SceneMetrics) → QuickPlotNode → HumanReview / ResultGeneration

节点职责：
- 快速生成图表以辅助人工直觉判断（分布、箱线、Top-N、时间对比等）。  
- 高亮异常区间、标注异常锚点（行级 evidence anchors）。  
- 输出静态、可导出且可归档的可视化证据（含 provenance）。

3. 核心功能（最小可接受集）
---------------------------
1) 快速分布感知（Zero-config）
  - 自动识别数值/金额/分类字段并生成直观图表。
2) 智能采样策略（大数据集性能优化）
  - **系统采样 (systematic)**: 均匀间隔采样，保持数据分布特征。
  - **蓄水池采样 (reservoir)**: 随机采样，保证每个数据点等概率被选中。
  - **分层采样 (stratified)**: 按指定分类字段保持各组比例代表性。
  - 自动检测大数据集 (>1000行)，透明应用采样并在图表标题标注。
3) 异常标注（可回溯）
  - 在图表中高亮离群点、极端值，并提供异常行计数与占比、行级 anchor 列表。
4) 样本数据持久化
  - 可选择性保存采样后的数据子集到存储，用于后续分析或复核。
  - 生成样本文件路径，方便前端展示和下载。
5) 审计友好导出
  - 生成带 metadata 的导出文件（图像 + provenance JSON），可入底稿。

4. 合规与治理边界（红线）
-------------------------
QuickPlotNode 绝不能：
- 改写或静默过滤原始数据；  
- 隐式产生风险判断或结论性描述；  
- 在无人工复核下替代签发/结论节点。

每张图必须包含治理标识：
- 数据来源节点与版本（e.g., ExcelLoader:file_hash, ColumnMapper:mapping_version）  
- 是否为清洗后数据说明  
- 明确免责声明：仅用于辅助人工理解，不构成审计结论

4. 采样策略详解
----------------
### 采样触发条件
- 当输入数据集超过 `MAX_DATA_POINTS` (默认 1000 行) 时自动触发采样。
- 图表标题会显示采样信息：`"(Sampled 1000/5000 points)"`。

### 支持的采样策略
1. **系统采样 (systematic)**
   - 每隔固定步长选择数据点。
   - 优点：保持数据的时间顺序和分布特征。
   - 适用：时间序列数据、保持周期性模式。

2. **蓄水池采样 (reservoir)**
   - 每个数据点都有等概率被选中。
   - 优点：完全随机，无偏采样。
   - 适用：一般统计分析，保证代表性。

3. **分层采样 (stratified)**
   - 按指定分类字段分组，保持各组比例。
   - 需要指定 `stratify_column` 参数。
   - 优点：保持分类变量的分布比例。
   - 适用：分类数据，保证各类别都有代表性。

### 样本数据持久化
- `persist_sample=true` 时保存采样后的数据子集。
- 生成 JSON 文件包含：采样索引列表、样本行数据。
- 文件路径返回给前端，支持下载和进一步分析。

5. 优化方向（产品与工程建议）
--------------------------------
1) 弱关联 Rule 的可视化高亮（提醒不结论）
  - 当某字段被 RuleCalculation 标记为高风险，QuickPlotNode 在相关图中自动高亮（红框/注记），并在 provenance 中写入 rule_id 列表。
2) 可视化证据可稽核化
  - 每次生成图表分配唯一 plot_id，图 + provenance JSON 可被 HumanReview 引用并写入 AuditLog。
3) 时间/批次对比视图（并列，不判断）
4) 与 HumanReview 的协作能力
  - HumanReview 可勾选“我已查看 plot_id”，并在决策中引用该 plot_id。
5) 轻量化 UI/Export 模式
  - 支持静态导出（PNG/JSON）和快速预览（分页表格），避免复杂交互导致误用。

6. 测试与验收要点（建议）
-------------------------
- 输出必须包含 provenance 字段并通过 schema 校验。
- 导出文件名与 metadata 必须可被 ResultGeneration / Export 节点解析并引用。
- QuickPlot 不应改变输入 DataFrame；在 mode=preview 下应严格只读。
- **采样策略测试**：
  - 大数据集自动触发采样，标题显示采样信息。
  - 三种采样策略产生不同的采样结果。
  - 分层采样保持各组比例代表性。
  - 样本持久化功能正确保存和返回样本文件路径。
  - 采样 metadata 包含策略信息和统计数据。
- 人工复核场景：创建一条带 plot_id 的 HumanReview 任务并完成签字后，确认导出/签发流程可以继续（若 ai_gov 阻断已解决）。

7. 风险与缓解
---------------
- 风险：图表被滥用作为“结论证据”。  
  - 缓解：在 UI/导出中强制展示 disclaimer 与 provenance，禁止自动化“结论传播”。  
- 风险：plot 导出绕过 governance guard。  
  - 缓解：所有导出必须走 ExportReportNode / SaveResultNode，并受 ai_gov guard 约束。

结论
-----
QuickPlotNode 的价值在于把“数据直觉”变成“可追溯的可视化证据”，减少不必要的人工复核，同时严格保持“可审计、不可裁决”的边界。建议把上述 PRD 作为 QuickPlot 的产品与合规规范并在实现时强制执行 provenance/disclaimer/export guard。
